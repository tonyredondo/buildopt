# Generated-code policy

This policy implements `F0-005` for every generated artifact checked into the
repository. Generated Go and Java clients remain deferred to `F0-022`; adding
the first descriptor snapshot here does not create those clients early.

## Source and inventory

[`dev/generated-artifacts.json`](./dev/generated-artifacts.json) is the
machine-readable inventory. Every entry names:

- one stable artifact ID and owning tracker item;
- every normative source path;
- every checked-in output path;
- the repository generator command and exact locked toolchains;
- the reviewable output format and accountable workstream.

An output must begin with a generated-file marker naming the repository
generator and source. Build directories, compiler caches, downloaded
dependencies, release bundles, benchmark results, and hand-authored golden
vectors are not generated source and do not belong in this inventory.

## Change procedure

1. Change the normative schema or IDL first.
2. Provision the exact toolchain from `dev/toolchains.lock.yaml`.
3. Run the manifest's generator command; never edit the output manually.
4. Inspect the semantic source diff and the complete generated diff together.
5. Run `./dev/check-generated-code` and all producer/consumer conformance
   checks for the changed contract.
6. Commit the source, manifest change when applicable, and generated output in
   the same change.

For the first tracked artifact:

```bash
./dev/bootstrap --toolchain protoc
./dev/generate-code --artifact local-events-v1-descriptor
./dev/check-generated-code
./dev/check-task-events-proto
```

## CI drift contract

`dev/check-generated-code` regenerates every manifest entry into a temporary
root with the locked toolchain and compares exact bytes with the checked-in
output. It also changes a temporary copy of the normative source and requires
that the generated bytes diverge. Missing outputs, manual edits, source changes
without regeneration, manifest/path drift, mutable tool selection, or a
generator that no longer reacts to the source fail the check.

The `F0-004` core CI lane runs this check after provisioning the listed
toolchains. CI never rewrites the checkout to make drift pass.
