# Calibration economics evidence

This bundle closes the preregistered
[calibration economics POC](../../../specs/poc-calibration-economics-v1.md).
It separates the one-time work required to discover and validate a reviewed
Structural Build Impact profile from the steady-state saving already qualified
by the terminal change-breadth matrix.

All six selective cells use the same immutable BuildOpt revision and
executable as their terminal value evidence. Each cell has two fresh phase
captures. Every capture preserves the real proposal, output contract,
equivalence contract, distribution log, and proposal log beside a SHA-256-bound
phase record. Private checkout and temporary roots in logs are replaced by
stable placeholders before hashing. The summary is regenerated by the strict checker; an independent
raw-source calculation also reproduced every cost and ceiling.

## Results

Times below are means in seconds. `Installed break-even` includes the combined
output-preflight/discovery command and candidate warm-ups. `POC break-even`
also includes the control warm-ups needed to prove comparative value. The cold
view adds exact offline Gradle distribution materialization; it rounds to the
same build count as the complete POC view for every cell and is retained in
[`summary.json`](./summary.json).

Repository checkout took 3.326 to 10.872 seconds and remains visible in every
phase record, but it is excluded from break-even because native Gradle and
BuildOpt require the same source. Offline distribution materialization took
0.658 to 1.324 seconds; network download was prepared before every phase clock
and is not presented as product overhead.

## Decision

The qualified steady-state value is real, but calibration is not cheap.
Installed-workflow payback is plausible for repeated CI/developer workflows:
10–15 qualifying builds for Groovy JAR and Kafka shadow-JAR cells, and 27–31
for Kafka Checkstyle. The full comparative POC costs roughly twice as many
builds because it intentionally pays for the native control arm too.

The dominant opportunity is therefore calibration efficiency, not another
steady-state percentage search. The next POC block should preserve and reuse
digest-bound preflight/discovery results and test bounded adaptive candidate
stabilization without weakening correctness, terminal value, drift, or native
fallback gates. Automatic or production activation remains disabled.
