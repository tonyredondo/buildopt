## Objective

Validate, from evidence generated by the current BuildOpt revision, whether a
repository-committed `./buildoptw` can learn and apply generic optimizations
that reduce cumulative wall time versus cache-equivalent optimized native
Gradle across ordinary chronological builds.

The experiment is successful only when the complete installed path creates
positive value in at least three of five public Gradle families while
preserving exact required outputs and adding no product-attributable failures.
Wrapper convenience, cache transport and safe fallback are necessary behavior,
but they are not acceleration claims.

## Fresh-evidence boundary

The new experiment starts from zero BuildOpt observations. Historical JSON,
profiles, timing rows, detector results and terminal decisions may explain why
the route changed, but they may not be copied, replayed, converted, averaged,
used as priors or counted toward any gate below. In particular, these files are
forbidden as experiment inputs:

- `benchmarks/results/current-longitudinal-raw-v1.json`;
- `benchmarks/results/current-longitudinal-cohorts-v1.json`;
- `benchmarks/results/sticky-wrapper-opportunity-gate-v1.json`;
- every AF, pre-sticky, SWL v1 or SWL v2 performance result; and
- any BuildOpt decision, profile, cache namespace or state directory created
  before the fresh contract freeze.

Repository Git history is not BuildOpt evidence. `SWL-FRESH-002` may select
chronological commits from current public histories, but it must run the
current package and regenerate every observation, trace, output digest,
candidate plan, cost and timing row after the freeze.

## Non-negotiable measurement rules

1. Freeze one BuildOpt source SHA and installed package SHA-256 before capture.
2. Use clean public checkouts and newly created Gradle/BuildOpt/cache roots.
3. Bind every row to repository revision, tree, workflow arguments, Wrapper
   distribution, JDK, runner resources, package digest and required outputs.
4. Compare identical workflows and native-cache opportunity. Writable
   candidate/control namespaces are separate and initially empty.
5. Measure outside both launchers with a monotonic clock; preserve pair order
   and every valid positive or negative result.
6. Required outputs must be byte-equivalent. A product-attributable failure is
   never discarded or replaced.
7. CI verifies code, schemas and checked evidence only. Performance thresholds
   are evaluated on the declared controlled runner, never on unstable hosted-CI
   wall time.
8. No repository-name, task-name, path-extension or hand-authored profile rule
   may enter product code or the evidence producer.
9. Missing input is not evidence of no opportunity. `INPUT_UNAVAILABLE` and
   `PRODUCER_FAILED` block the breadth gate; they can never create stop evidence.
10. Percentages from different mechanisms or workloads are reported
    separately and are never added.

## Execution contract

### SWL-FRESH-001 — Complete generic producers

Implement one capture command that invokes both existing detector families and
emits a typed result for each detector and repository:

- `TESTABLE_ACTIONS`: one or more complete independently executable actions;
- `NO_OPPORTUNITY`: the producer completed and proved that no safe action
  exists for the observed workflow;
- `NOT_APPLICABLE`: the producer completed and the workflow contains no
  compatible task/action class;
- `INPUT_UNAVAILABLE`: required generic Gradle evidence could not be produced;
- `PRODUCER_FAILED`: BuildOpt failed while producing or validating evidence.

Only the first three states are conclusive. The block is complete only when
synthetic Kotlin DSL and Groovy DSL fixtures prove positive, no-op,
not-applicable, incomplete-input and producer-failure paths for both detector
families without repository-specific rules.

Every task-contract action must bind the task implementation, declared inputs,
declared outputs, cacheability, requested-workflow reachability, reversible
patch transaction and validation command. Every graph action must bind the
full graph, candidate graph, omitted critical path, exact output closure,
candidate plan and isolated apply/revert transaction. Costs remain typed
unavailable until measured; they are never zero-filled.

Owned implementation paths:

- `internal/durablecatalog/public_evidence.go` and tests;
- `cmd/sticky-evidence-capture/main.go` and tests;
- `fixtures/sticky-evidence-capture/`;
- `dev/run-sticky-evidence-producers`;
- `dev/check-sticky-evidence-producers`; and
- the current tracker, architecture map, validation reference and one-page
  handoff.

Focused checks: Go race tests for touched packages, both producer scripts,
fixture negatives, `go vet ./...`, plan/tracker/documentation validators and
`git diff --check`.

### SWL-FRESH-002 — Fresh cohort and capture

Freeze Spring Framework, OpenTelemetry Java Instrumentation, Apache Kafka,
Micronaut Core and Apache Groovy from their current public branches. Select 20
first-parent comparable commits plus ten chronological reserves per family
without looking at BuildOpt outcomes. Freeze workflow, required outputs, JDK,
Wrapper distribution and resource policy before execution.

Create a new result directory containing `contract.json`, `cohort.json`,
`observations.jsonl`, `producer-results.json`, `output-manifest.json`,
`exclusions.json`, `report.json` and `sha256sums`. Every generated timestamp
must be after the contract freeze and every row must bind the frozen package
digest. The checker rejects any legacy evidence digest, reused state root,
missing trace/output binding or post-result cohort edit.

### SWL-FRESH-003 — Five-family opportunity gate

First require conclusive producer outcomes for both detectors in all five
families. If any result is `INPUT_UNAVAILABLE` or `PRODUCER_FAILED`, the block
is `BLOCKED_INCOMPLETE_INPUT`; it is not a failed opportunity gate.

After completeness passes, independently recompute recurrence, projected
critical-path saving, trial/publication/execution cost and compatible-build
payback. At least three families must expose a complete action to open timing.
A complete screen with fewer than three may produce legitimate stop evidence
for `SWL-FRESH-006`; an incomplete screen may not.

### SWL-FRESH-004 — Installed active-value gate

For every admitted action, use the installed `./buildoptw` path for exactly
eight balanced alternating candidate/native pairs on the controlled runner.
Require exact outputs, zero product failures, positive mean and conservative
lower bound, no candidate p95 regression, complete costs and native fallback.
At least three families must pass.

### SWL-FRESH-005 — Chronological campaign

Run the frozen current package over the selected chronological commits with
separate persistent per-arm state. Each family needs at least 15 comparable
requested builds from its 20 primary commits. Rows must identify the actual
lifecycle state and action executed. No historical BuildOpt row or cached
decision is importable.

### SWL-FRESH-006 — Terminal decision

Continue only if correctness, at least three-family breadth, positive complete
portfolio value, independently positive lower confidence in at least three
families, payback, native-retention overhead and zero product-failure gates all
pass. Otherwise stop and name the failed criteria. Incomplete inputs produce
`INCOMPLETE`, not a stop or continue decision.
