# Automatic breadth transfer

This POC runs the unchanged, zero-manual-file customer path across Spring
Framework, OpenTelemetry Java Instrumentation, Apache Kafka, Micronaut Core and
Apache Groovy:

```bash
buildopt optimize <the repository's existing Gradle workflow>
```

The five public revisions, source mutations, workflows and toolchains remain
those frozen by [`poc-generic-profile-matrix-v3.json`](./poc-generic-profile-matrix-v3.json).
That keeps the comparison tied to the same customer work already used by the
balanced qualification matrix. The automatic path receives no retained
manifest, graph, output contract, profile or repository-specific hint.

## What this block answers

For each repository, the installed command must either:

- discover a complete structural candidate, prove exact outputs and fallback,
  and report its measured value and payback; or
- retain optimized native Gradle with the exact generic reason.

A row is evidence even when it does not qualify. This block is intended to
find generic graph, task, variant, ABI, output or economic blockers. A blocker
may be corrected only when the correction is repository-neutral and preserves
native fallback. No repository name, frozen changed path, expected task or old
percentage may influence the product decision.

## Execution and evidence

Subjects run sequentially on the local 12-CPU Linux host with a fresh checkout
and private Gradle home. Wrapper and dependency preparation may happen before
calibration, but no failed observation may be removed. Each subject receives
eight balanced pairs, a 30-minute learning budget and a maximum 30 matching
build payback. The runner preserves the raw optimize result and generated
state, then deletes that subject's checkout and Gradle home before continuing.

The terminal summary reports each repository separately. Percentages are not
averaged across repositories or added to another mechanism. Existing timing is
context only and cannot replace a fresh automatic observation.

## POC boundary

This is idea validation, not production promotion. Selection remains confined
to the explicitly invoked owner command. Production authority, soak testing,
design-partner requirements and Test Optimization are out of scope. If exact
evidence is unavailable or the candidate cannot repay, optimized native Gradle
remains authoritative.
