# Change-aware producer closure POC contract

Status: `HYPOTHESIS_PREREGISTERED`.

Execution status: the frozen hypothesis remains unchanged. `SWL-CHANGE-001`
has completed its fresh five-family evidence capture; `SWL-CHANGE-002` is the
next independent gate. This note reports execution progress and does not amend
the preregistered contract or thresholds below.

## Question

Can BuildOpt use complete Gradle producer ownership plus the actual paths
changed between adjacent commits to omit unaffected producer work more broadly
than the stopped single-revision detector set, while preserving every required
output byte and retaining optimized native Gradle on uncertainty?

This is an opportunity hypothesis, not a performance result. It authorizes a
new evidence producer and breadth screen. It does not authorize timing,
activation, promotion, or reuse of the single Spring action.

## Material difference from the stopped detector set

`DECLARED_GRAPH_SCOPE_V1` searched for a safe smaller graph using one unchanged
revision. It found no action in all five public families. The replacement
`CHANGE_AWARE_PRODUCER_CLOSURE_V1` evaluates a real adjacent-revision change
against the complete requested task graph, task-to-output producers and exact
required-output closure. A change may therefore make only a strict subset of
the requested workflow necessary even when the entire unchanged workflow was
internally consistent.

This is not the historical profile/materialization experiment. No historical
profile, timing row, decision, cache namespace or transported byte is an input.
The new producer must derive each candidate from the current binary and fresh
ordinary builds.

## Safe action

A testable action exists only when all of the following are complete:

1. the original requested workflow and its complete task dependency graph;
2. every required output and its direct and transitive Gradle producer lineage;
3. the changed paths between two adjacent public revisions;
4. generic ownership from changed paths to consumed task inputs;
5. the affected producer closure and the complementary unaffected closure;
6. byte-exact availability of every required output omitted by the candidate;
7. an isolated apply/revert transaction; and
8. the original workflow as a fail-open fallback before repository mutation.

Missing, ambiguous, cyclic, drifted or unowned evidence yields
`INPUT_UNAVAILABLE` or `NO_SAFE_ACTION`; it never yields an optimistic action.

## Gates

- All five public families must produce conclusive inputs.
- At least three of five must expose a complete action before any timing.
- No repository-name, task-name, path-extension or hand-authored profile rule
  may enter the detector.
- Required outputs remain byte exact and the product-failure budget is zero.
- Hosted CI checks schemas, fixtures and frozen evidence only. Wall-time gates
  remain on the controlled runner.
- If breadth passes, installed value is measured before any chronological
  campaign. If it fails, timing remains `NOT_MEASURED_NOT_AUTHORIZED`.
