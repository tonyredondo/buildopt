# Change-Scoped Candidate Correctness v1

Status: `CSCPC-001` contract frozen; public candidate correctness is authorized.

This route tests the four action families admitted by native critical-path
discovery. Each row uses the exact target revision, aggregate workflow,
structural partition and native output manifest already bound by CSCPN. The
generic installed BuildOpt path runs exactly three requested invocations from
empty state: two optimized-native observations followed by one
change-scoped incremental candidate.

The candidate workspace is cleaned before every invocation. A conclusive row
requires native/native/candidate execution modes, successful exit codes, the
expected generic candidate entrypoint, no tracked public-source mutation and a
byte-exact manifest match for every required output against the fresh CSCPN
native baseline. Repository or task names cannot affect selection.

This block is correctness only. Invocation duration is diagnostic metadata,
not a timing sample. It does not run balanced pairs, installed economics or a
chronological campaign. The gate requires 4/4 exact candidates and zero
product failures. Failure stops timing; success authorizes only a separately
frozen paired-value contract.

Capture is sequential, limited to twelve Gradle starts, three per family,
30 minutes per invocation, 12 workers and at least 8 GiB free before each
family. Temporary checkouts, Gradle homes and materialization payloads are
removed after compact digest-bound evidence is retained.
