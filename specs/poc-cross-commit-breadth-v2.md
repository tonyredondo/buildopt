# Cross-commit breadth V2

## Purpose

`POC-CROSS-COMMIT-BREADTH-V2-001` tests whether the unchanged automatic
structural profile can retain value across later public commits in three
additional Gradle families: OpenTelemetry, Ktor and Groovy. It broadens the
existing Kafka and Spring evidence only when at least two new subjects produce
an exact selected replay and positive cumulative economics.

## Frozen method

The subject file freezes one public direct-child qualification change and the
first three first-parent descendants that keep the qualification Wrapper for
each repository. The commits were selected from topology and Wrapper identity
before any timing. Each qualification runs the producer-bound quarantine
protocol with 18 ordinary invocations, eight alternating calibration pairs, a
fresh Gradle process, persistent dependency state and the optimized native
workflow as control.

A qualification needs at least seven positive pairs, a positive paired 95%
interval, non-regressive candidate p95 and at most 30 builds to repay its
cost. Independent native roots must establish exact transported bytes; any
volatile producer is rebuilt locally. Descendant observations use the same
installed executable and require exact declared outputs. Native fallback,
selection savings, fallback variation and calibration/publication cost remain
separate.

## Decision

An individual subject is claim-eligible only when it qualifies, passes the
portability gate, selects at least one descendant with exact outputs and ends
the observed window with positive cumulative net savings. The block broadens
the cross-commit conclusion only when at least two of the three frozen
subjects are claim-eligible. Percentages are never averaged across
repositories and a negative or incompatible observation remains evidence.

## Run

```bash
./dev/run-cross-commit-breadth-v2 /absolute/evidence/directory
./dev/check-cross-commit-breadth-v2 /absolute/evidence/directory
```

One repository key may be supplied as the second runner argument so the long
matrix is restartable by subject. `--summary-only` assembles the terminal
report after all three subject results exist.

## Boundaries

This is bounded owner-operated POC evidence. It grants no production
activation, adds no repository-name rule, requires no soak or design partner,
and does not implement Test Optimization.
