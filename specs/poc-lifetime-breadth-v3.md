# Ordinary-build lifetime breadth V3

This POC runs one unchanged installed BuildOpt executable over the frozen
Spring Framework, OpenTelemetry Java Instrumentation, Apache Kafka, Micronaut
Core and Apache Groovy public first-parent windows. It asks whether the generic
one-command path creates cumulative customer value after paying for learning,
publication, safe fallback and revision-bound output correctness.

The machine contract is
[`poc-lifetime-breadth-v3.json`](./poc-lifetime-breadth-v3.json). Its frozen
subjects are the exact public revisions and workflows in
[`poc-qualified-lifetime-v2.json`](./poc-qualified-lifetime-v2.json); V3 does
not choose a more favorable repository, task or change after seeing results.

## Learning and lifetime rules

Only requested ordinary builds may produce duration, structural, portability
or volatility evidence. A baseline stops immediately when the first-parent
history predicts fewer than five compatible matches. The first complete
control/candidate pair stops when its saving is non-positive or its learning
cost cannot repay within five compatible matches. Positive first-pair
economics only authorize continued learning: qualification still requires
eight alternating pairs, at least six positive pairs, a strictly positive
paired interval, non-regressive candidate p95, exact outputs and successful
full-graph fallback.

Qualified profiles may be rebound only through the canonical structural
fingerprint. Evidence ancestry and exact output revisions remain separate, so
structural compatibility never makes stale bytes current. Every uncertain,
global or incompatible descendant runs optimized native Gradle.

For each repository the result retains complete signed wall-time economics:
discovery and capture, ordinary qualification, publication, selected replay
saving and directly measured native-retention wrapper cost. Repository
percentages are not averaged and mechanism percentages are not added.

## Acceptance and interpretation

The breadth hypothesis passes only when all five subjects use the same
executable, every requested build preserves its required outputs, product
failures remain zero, at least three repository families finish net positive
and at least half of the non-global structurally eligible descendants select a
profile. Missing those value thresholds is a valid terminal POC result; the
thresholds are not moved after observation.

This protocol does not authorize production activation, soak testing, design
partner work or Test Optimization. It is a bounded experiment to decide
whether the generic BuildOpt idea has enough repeatable wall-time value to
continue.
