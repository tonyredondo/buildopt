# Configuration-Input Native Corrections v1

`CONFIGURATION_INPUT_NATIVE_CORRECTIONS_V1` tests a fresh source-neutral
reviewed-native correction class for unsupported configuration-time external
state reads. A strict Gradle Configuration Cache problem must bind to
repository-owned source and to a supported `ProviderFactory` or `ValueSource`
replacement before controlled materiality, candidate correctness, paired value,
or owner review can open.

The detailed contract and ordered execution route are in the
[CINC tracker](../docs/plans/configuration-input-native-corrections-poc.md); the
[machine contract](./poc-configuration-input-native-corrections-v1.json) is the
executable authority.

`CINC-002` freezes ten public families and two ordered reserves per family in
the [subject manifest](./poc-configuration-input-native-corrections-v1.subjects.json).
Selection used only owner workflows with Configuration Cache explicitly
disabled; it did not inspect strict diagnostics or detector syntax. Build
scans are also disabled for all subsequent starts after Mockito's project
default unexpectedly published one during preflight. That telemetry event is
retained as an audit fact and supplies no selection or performance evidence.

WCNCP and every predecessor result are diagnostic context only and supply zero
CINC rows. The first cohort excludes WCNCP primaries and the historical
GraphQL, Micronaut, Spring, and Elasticsearch recipe families. Thresholds stay
at 500 ms, 2%, three actionable material families before candidates, and zero
product failures.

CINC never suppresses Configuration Cache problems, edits public source,
applies or merges a proposal automatically, or uses repository/task names as
classification inputs. Hosted CI owns contracts and correctness, never wall
time.
