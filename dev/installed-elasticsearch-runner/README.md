# Installed Elasticsearch protocol qualification

This Linux AMD64 command compiles the accepted EIC start allocation, checks
budget arithmetic and qualifies capture using real local fixture processes.
It also admits the three ordered, unpatched native preparation rows through
`native-prepare` and the two following native diagnostics through `native-diagnose`,
under the owner's explicit budget extension. It also implements the accepted
native-date comparator and separately frozen real Gradle mutation qualification.
The daemon-log reader and installed wrapper/native boundary checker also have
retained local qualification. The approved third campaign has independently
verified C12, M24 and all 52 owner methods with twelve nested TestKit builds.
The experiment is now closed at `STOP_INSTALLED_PERSISTENT_UPLOAD_DEADLINE`:
fresh persistent uploads and the actual installed Elasticsearch help path miss
the unchanged 100-ms deadline on this host. Value/chronology adapters remain
partial and V/L/H/O unrun. The
[terminal finding](../../docs/findings/buildopt-elasticsearch-installed-experiment-2026-09-08.md)
records the evidence and bounded conclusion.

The [experiment plan](../../docs/plans/installed-elasticsearch-native-correction-v1.md)
defines the public proof and stop point. The older CNC runner and its closed
decision are unchanged. Local fixture qualification is offline. Native preparation
uses the pinned upstream source and Gradle dependencies and a transient user
systemd service to own and clean up each process tree.

## Qualification and commands

Run the bounded local test gate:

```bash
./dev/check-installed-elasticsearch-protocol
```

Build a retained executable before capture. `go run` removes its temporary
executable, which would invalidate the later executable-byte check.

```bash
mkdir -p .tools/state/eic-protocol-v1
./dev/run --toolchain go -- go build -mod=readonly -o .tools/state/eic-protocol-v1/runner github.com/tonyredondo/buildopt/dev/installed-elasticsearch-runner
.tools/state/eic-protocol-v1/runner plan
.tools/state/eic-protocol-v1/runner budget --charged-seconds 4440
```

The budget example represents the **start** of this milestone, not a fresh
window. Use the latest cumulative charge from the tracker. `budget --input`
accepts an absolute JSON file with `chargedSeconds`, `preparationSeconds`,
`managementSeconds`, optional `ceilingSeconds` and `estimates`. The equivalent
`--ceiling-seconds` flag represents an owner-authorized extension; omitting it
preserves the historical 7,200-second default. Costs never reset. Each estimate contains a profile from
`unsizedProfiles`, a positive `upperBoundMs` and `provenance`.
Only `OPERATOR_ESTIMATE` participates in hypothetical arithmetic;
`HISTORICAL` and `LOCAL_FIXTURE` remain unsized. Every result retains
`publicExecutionAuthorized: false`. `FITS_ESTIMATE_ONLY` is not runtime proof,
owner acceptance or permission. Invalid input exits nonzero; a valid negative
budget decision is JSON, so callers must inspect `decision`.

The calculation includes all 300 outer requests, their twelve nested starts,
two infrastructure reserves, 120 seconds of quiescence and 600 seconds of
closure. Nested durations belong to their enclosing functional-test bounds
and are not added twice. Status calls and other non-Gradle work belong in
`managementSeconds`; acquisition belongs in `preparationSeconds`. Profiles
separate phases, workloads, arms and observation modes. No retry executes
automatically. The two reserve slots are capacity, not extra observations.

`audit --cache ABSOLUTE_CACHE --package ABSOLUTE_PACKAGE --jdk-archive
ABSOLUTE_ARCHIVE` verifies the retained source/wrapper files, six immutable
commit responses and parent edges, JDK archive and actual package bytes.
It emits `STATIC_BYTES_ONLY`. A downloaded JDK archive does not prove which
launcher, daemon, compiler or runtime Elasticsearch resolves.

`fixture --root NEW_ABSOLUTE_DIRECTORY --package ABSOLUTE_PACKAGE` runs the
300 outer fixture processes and twelve nested fixtures within a 120-second
parent deadline. Its root must be new; an occupied or partial capture cannot
be restarted or overwritten. The fixture keeps three independent working
roots, sealed requests, input bytes, start reservations, boot-clock boundaries,
split raw logs, exit/signal facts, nested process records and output copies.
The package is hashed, not installed or executed by this fixture. The separate
installed integration gate supplies package execution proof.

The command prints `receiptSha256`. Retain that pin outside the capture and
pass it to `check --root ABSOLUTE_DIRECTORY --receipt-sha256 SHA256`.
The checker hashes the retained files and reconstructs every required row
before comparing the summary. It rejects missing/duplicate/reordered rows,
changed inputs or outputs, forged summaries, missing/extra nested records,
lost failures, undeclared files and overlapping process boundaries. Checking
is read-only and does not rerun children. A digest provides tamper detection
against the retained external pin, not third-party attestation of this host.

The fixture uses Linux process groups and parent-death signals. This proves
its own child lifecycle; it does not prove ownership of Gradle daemons or
discover uninstrumented TestKit builds. Each stream is limited to 1 MiB,
the capture root to 64 MiB, and the fixture requires 1 GiB free. Tests may
create additional isolated copies to exercise tampering, then remove them.

All captured rows are `LOCAL_PROTOCOL_FIXTURE`, with performance authority
false. The toy output producer proves capture and checker behavior only.
Its mutation labels and revision labels are not executions of Elasticsearch
code, Gradle cache invalidation, signed patch application or real chronology.
Expected fixture failures use exit 19; that exit is not an Elasticsearch
failure contract. Partial attempts remain inspectable but fail completeness.

## Accepted native-date comparison

`native-output-audit` accepts the same capture arguments as `native-compare`.
It rehashes all outputs and evaluates all accepted date differences, then lists
every unapproved difference with task ownership. Its `gatePassed` field refers
only to output equality; `valueAdmitted` remains false. This diagnostic does
not change the strict comparison contract.

## Correctness campaign adapters

`correctness-plan` prints the C/M/T allocation and exact source/cache
transitions. `correctness-run --input PREPARATION --sha256 SHA256` opens only
the twelve C rows after exact source preparation and installed-capture proof.
It freezes its runner, package, private states, JDK, wrapper and commands before
the first start. Exclusive reservations prevent replay; each native process is
owned by a transient service. `correctness-check` independently reconstructs
the completed receipt and rejects partial or stopped captures.

The local backend uses loopback TLS and task-private credentials. Frozen
requests contain a credential file reference, never its value. The installed
launcher scrubs those controls before Gradle. `BUILDOPT_EIC_NATIVE_TRACE` is a
Linux diagnostic opt-in: it records the real native process interval and result
after the child exits, and cannot alter native failure behavior. It is not a
performance timing mode. Graph collection uses a JVM property that survives
the private-environment scrub; the older frozen collector is unchanged.

`mutation-freeze` with `--correctness-receipt` and `--correctness-sha256`
requires a complete verified C receipt. This opens fresh `M001`-`M024` rows,
distinct from historical local `QM` qualification, with eight CPU slots and
eight workers. No old qualification row is reclassified. `mutation-run` and
`mutation-check` consume the resulting pinned freeze/receipt as before.

`owner-test-freeze --input MUTATION_RECEIPT --sha256 SHA256` requires those
verified public M rows. `owner-test-run` captures the four original upstream
test commands; `owner-test-check` requires every one of the 20 unit methods
and six functional methods per arm, with no failure or skip. Ordinary TestKit
daemon logs must account for exactly twelve nested builds inside their outer
invocations. Test evidence has a separate root and cannot alter sealed C rows.

The [C003 finding](../../docs/findings/buildopt-elasticsearch-correctness-output-contract-2026-09-07.md)
retains the first campaign's stop. The owner subsequently approved the exact

The second campaign verifies C001-C007 and stops at C008 on the unchanged
date-producer rule. The third campaign subsequently verifies C12 and M24 under

The owner has separately approved the bounded date-generation/Checkstyle
contract. The optional `provenanceRuntime` binding
enables it only for a new campaign with qualified implementation and retained

The composite profile adds `--composite-decision ABSOLUTE_DECISION` and
`--composite-decision-sha256 SHA256` to `owner-test-freeze`. It binds the exact
`:build-tools-internal:test` and `:build-tools-internal:integTest` root commands,

`owner-test-continue --input PARTIAL_RECEIPT --sha256 SHA256` only accepts the

Persistent transport and installed delivery probes are opt-in tests with new
private roots and separate allocations. Default protocol qualification skips
their public Gradle launches. `TestRetainedInstalledDelivery` replays the two
actual UI rows without Gradle when `EIC_INSTALLED_DELIVERY_REPLAY` names their
retained root. It checks the product's privacy-redacted arguments alongside the

[`provenance-runtime-contract-v1.json`](provenance-runtime-contract-v1.json)
adds no date fields or paths. Reused date artifacts must match an earlier
verified executed artifact in the same campaign and source revision, including

invocation window; current source-manifest propagation is checked separately.
Only fully verified and sealed rows become available to later rows.

The single Checkstyle `main.xml` report permits replacement of the verified
producer prefix inside direct `file name` attributes. Every other XML byte stays
exact. Reused reports require an earlier executed artifact or the one explicitly
pinned historical seed. Runtime qualification binds source bytes compiled into
the runner, tests, retained replay, and the separate owner decision.

## Approved metadata comparison

[`metadata-output-contract-v1.json`](metadata-output-contract-v1.json) binds the
227 exact JavaCompile output selectors, including the one absent file, and the
single RAT report. The pinned Gradle 9.7.1 serializer decodes every compilation
field. A typed, length-framed projection preserves values, nullness and list
order; only map/set iteration order is irrelevant. Decode/re-encode collection
cardinality histograms reject duplicate members silently collapsed by Gradle.
Full input consumption, explicit decoded types and bounded inputs are required.
The helper runs outside native process timing and never writes retained files.

`python3 dev/installed-elasticsearch-runner/metadata/qualify.py --help` describes
the standalone Java qualification. It binds actual runtime jars to the admitted
seed and the JDK to its prior qualified inventory, compiles with warnings as
errors, and exercises malformed, duplicate and changed-value cases plus all
226 real metadata pairs. It launches no Gradle builds. The runtime classpath
excludes `lib/api` declaration stubs. The resulting helper, JDK, every runtime
jar, source, tests, approval and qualification evidence are frozen inputs.

RAT comparison preserves all original XML bytes except the root timestamp and
the verified producer prefix of each resource name. Resources retain their
identities and order; license content and approvals remain exact. Executed
timestamps must intersect their producer's execution at second precision.
Cached reports require byte-identical earlier provenance. The specifically
approved original D001 report is the seed trust anchor; D001 retained it
`UP-TO-DATE`, so its timestamp is not attributed to D001 execution.

`metadata-compare` uses the `native-compare` capture arguments plus `--metadata`
and `--metadata-sha256`. It requires the approved, qualified runtime and leaves
`valueAdmitted` false. Comparing old captures under this explicit new contract
does not promote their failed campaign receipt. `native-compare` remains exact
apart from its original manifest-date rule.

## Accepted native-date contract

rehashes the complete retained output trees, inventories and raw diagnostics,

[`native-date-contract-v1.json`](native-date-contract-v1.json).

`657cc250f39669f2307a04a1af46b7a93fad1308a19407754d58b75b8809fa63`.

of 64 output files. Dates must be valid UTC values within their own native
invocation; changed files require executed owners and propagated manifest

framing, compressed non-manifest bytes, paths, types and modes remain exact.
Malformed, duplicate, unsupported or ambiguous inputs are refused.

Eligibility now reports executed owner work of at least 500 ms and at least

## Real Gradle mutation qualification

`mutation-freeze --root NEW_ABSOLUTE_ROOT --source CLEAN_B0_WORKTREE
--gradle LOCKED_GRADLE_DIRECTORY --jdk LOCKED_JDK_DIRECTORY` freezes 24 local
rows for six mutations on the original and annotation-only task classes.
It requires the exact owner and problem-reporting sources from B0, Gradle
9.7.1, Temurin 21.0.12+8, and a retained runner binary. The standalone fixture
copies those two licensed source files and adds a configuration adapter; it
does not change the Elasticsearch worktree. Each arm owns a separate empty
Gradle user home and temporary directory.

Pass its external binding to `mutation-run --input ABSOLUTE_FREEZE --sha256
SHA256`. Each before row runs a seed task and the target task using the same
owner class in one Gradle invocation. The candidate must actually restore the
seed's cache key. The after row changes rules, exclusions, a relative file
path, source presence, UTF-8 bytes, or the relative root directory, without
executing a new seed. Successful mutations must execute with a changed cache
key and stable implementation/classloader hashes. Source removal must report
`NO-SOURCE`; malformed UTF-8 must fail for its actual UTF-8 read error. Exact
control/candidate output equality includes retained markers and absence.
It does not assume that a skipped or failed action removes prior outputs.

Limits are frozen before the first start: 24 starts, 120 seconds per Gradle
process, 130 seconds per owned systemd service, 45 minutes total, 5 GiB output
and at least 20 GiB free. Invocations are serial, offline and use two workers
on CPUs 0–3. Every service owns its full process tree. Failed qualification
preserves raw evidence and seals a failed receipt; occupied runs cannot replay
or resume and no retry is automatic. A corrected qualification needs a new
freeze and must retain the earlier charged starts.

`mutation-check --input ABSOLUTE_RECEIPT --sha256 SHA256` independently
reconstructs all 24 rows without starting Gradle. It verifies raw operation
parentage, graph ownership, input bytes, process boundaries and outcomes,
cache restoration/invalidation, output copies and closed service identities.
Every result is `LOCAL_REAL_GRADLE_MUTATION_QUALIFICATION`, with value authority
false. These rows qualify the adapter; they do not replace public C/M/T or
installed three-arm value evidence.

## Nested starts and installed boundaries

`testkit-count --input ABSOLUTE_LOG_MANIFEST --sha256 SHA256` reads an
externally pinned `buildopt.eic/testkit-logs/v1` JSON document containing a
`logs` array of absolute `path`/`sha256` bindings. It reconstructs each Gradle
daemon request's receive, command-start, execution-start, execution-end and
command-finish records. It verifies daemon PID/runtime identity and refuses
missing, duplicate, overlapping or truncated lifecycles. A reused JVM can
contain multiple starts. Partial results remain nonzero exits and cannot
support completeness. The reported wall-clock fields correlate requests;
they are not performance timings or independent build outcomes.

Actual TestKit qualification invoked the API four times in one daemon,
including Configuration Cache reuse, task failure and settings failure.
The daemon reader matched every request to the independent caller interval.
An experimental init-script listener missed the cached-configuration request;
that observer was removed from the implementation. The final qualification
uses Gradle's ordinary daemon logs with no observer script.

`boundary-check --input ABSOLUTE_RECEIPT --sha256 SHA256` independently
rehashes a retained installed-boundary capture. It checks four ordered outer
and native process intervals, their owned services and the exact executing
helper bytes. Three installed observations must bind their actual argument
vectors and package, retain the native outcomes, report durations inside the
measured intervals, and arrive after the child ends and before the outer
entrypoint ends. The checker grants no performance authority.

The opt-in
[`TestStickyWCNCPInstalledBoundaries`](../../internal/launcher/sticky_wcncp_boundaries_test.go)
creates that local qualification with the retained release package. Build its
test executable to a persistent task directory, then select it with
`-test.run=^TestStickyWCNCPInstalledBoundaries$`. Inputs are
`EIC_BOUNDARY_ROOT` (new), `EIC_TEST_PACKAGE`, `EIC_BOUNDARY_GRADLE` (executable),
`EIC_BOUNDARY_JDK`, and externally pinned `EIC_BOUNDARY_RUNTIME_MANIFEST` /
`EIC_BOUNDARY_RUNTIME_SHA256`. `EIC_BOUNDARY_SERVER_ROOT` selects a new private
backend directory; the acknowledged-delivery qualification used bounded tmpfs.
The test freezes four Gradle starts, a 120-second service bound, a 1 GiB
workload cap and a separate 64 MiB backend cap. Retain the executable because
the generated native helper references and hashes its actual bytes.

This fixture exercises the recorder's controlled-input branch with local
fixture bindings. Its enclosing capture remains
`LOCAL_INSTALLED_BOUNDARY_QUALIFICATION`; it cannot enter Elasticsearch value
gates. Helper writes and TLS fixture setup add instrumentation cost, so these
durations do not estimate wrapper overhead. On this host, persistent backend
writes took 119–131 ms and exceeded the unchanged 100 ms upload deadline.
Native success was preserved and observations remained queued. A separate
transport replay diagnosed that result without new Gradle starts. The final
tmpfs-backed qualification verified actual acknowledgements and an empty

## Native preparation

Build a separate retained executable under the native campaign root; do not
overwrite the executable pinned by an earlier fixture or native request.
The root must already contain the verified shared subject worktrees at
`arms/N0`, `arms/N1`, `arms/W1`, their `repos/elasticsearch.git` common directory,
the locked `runtime/jdk-21` and an empty `attempts` directory.

```bash
.tools/state/eic-native-v1/runner native-prepare --root /home/tonyredondo/repos/github/tonyredondo/buildopt/.tools/state/eic-native-v1 --slot P001
```

P002 and P003 require successful, input-verified predecessors. The command
reserves each slot once and retains requests, source/runtime bindings, raw
streams, process boundaries, exit/signal facts and cgroup ownership. It never
retries a failed slot or admits diagnostics, mutations or candidate timing.
Each native child is limited to 600 seconds, with a 610-second systemd service
backstop. Attempt-boundary disk checks require less than 30 GiB under the root
and at least 40 GiB free. Separate per-arm caches and temporary directories
preserve the native repository configuration. `HOME` is omitted from the child
environment; Java's user directory is set to owned state with `-Duser.home`.

`EIC_REQUIRE_SYSTEMD=1` makes the real cgroup cancellation test mandatory during
local qualification. Native preparation itself always requires user systemd;
it has no weaker process-group-only fallback.

`native-diagnose --root ABSOLUTE_ROOT --slot D001` (then D002) requires all
three successful P rows. It preserves their ordinary output/cache state and
adds only the embedded graph/output collector and Gradle operation tracing.
The request pins the collector's bytes. The existing critical-path analyzer
joins every graph task with its completed operation, preserving raw outcomes.
The capture includes all main-build task output declarations, file/directory
modes and bytes, explicit absence and retained copies. Included build-logic
outputs remain separate from the main-build owner-output contract.

The separately authorized clean-workspace scenario uses `clean-seal --root
ABSOLUTE_ROOT` to freeze the complete pristine worktree and populated private
state. Retain its printed SHA-256 outside the capture. Then use
`native-clean-diagnose --root ABSOLUTE_ROOT --slot CD001 --seed-sha256 SHA256`,
restore the exact same snapshots, and use CD002 with the same pin. These slots
have their own root and ledger and never advance the closed P/D sequence.
The runner verifies file bytes, types, modes, mtimes and symlink targets both
before reserving the start and inside the owned service. Seed sealing records
state; preparation must separately prove it is pristine and caches are populated.
The `repos/elasticsearch.git` entry may point to the verified existing shared
Git directory; the resolved identity, exact source commit and clean tree are
checked before and after execution. Preserve prior worktrees and failed attempts.

Native materiality requires executed work on the critical path, at least
500 ms and 2% of that path. An up-to-date task cannot count as saved execution.
A failed materiality gate does not change the captured Gradle exit status or
permit candidate timing. The diagnostic report is neither a V row nor a speedup
measurement. `EIC_TEST_GRADLE` and `EIC_TEST_JDK` enable the actual isolated
Gradle diagnostic fixture; it exercises first/repeat task outcomes and exact
output retention without running Elasticsearch.

This frozen gate uses the longest hard-dependency chain by task wall duration.
It does not model project locks, shared artifact calculation or worker waits.
An off-chain result therefore does not prove that shortening a task cannot
shorten the workflow. The subsequent resolution investigation in the tracker
demonstrated that limitation with an owned JFR recording and four real Gradle
fixtures. Existing gate results and exact-output contracts are unchanged.
